DoD EVIDENCE:

C-2 (child process; native crash degrades to the existing fail-open warning) — lib.rs call site + ChildOutcome::into_result onto AppError::Diarization. C-3 (regression test on the known crash input, ignored-by-default) — tests/diarize_isolation_regression.rs, two #[ignore] tests following the diarize_integration.rs / wp50_tuning_regression.rs convention, resolving the worker via CARGO_BIN_EXE_whisper-pilot because current_exe() under cargo test is the test binary. Executed three times across the run; last run 2 passed in 45.9s.
C-4 (inactivity kill, no orphan) — supervise polls try_wait, kills on an injected inactivity budget, and reaps. Tested for both the kill and the no-orphan assertion (ps-based), and for inactivity-not-wall-clock. Code review then found a leak this criterion's wording did not cover: quitting the app mid-run left the child reparented and still holding the models, a regression versus the previous spawn_blocking thread. Fixed by having the child watch stdin for EOF (the one death signal that arrives however the parent went, including SIGKILL) and terminate with libc::_exit, plus an age-based sweep of transports older than 6h for the hard-kill case. Verified live: the real worker ran inference for 4s while a fifo was held, then exited code 5 within 2s of the holder dying, leaving no crash report.
C-5 (four outcomes distinguished and tested) — ChildOutcome::{Completed, Crashed, Failed, TimedOut}, returned un-collapsed so WP-57 can branch on them. Review caught that outcome_after_kill discriminated on the Crashed variant rather than on SIGKILL, which would have laundered a real SIGBUS landing inside the kill window into TimedOut — losing exactly the outcome WP-57 retries on. Now matches signal == 9, with unit cases for both.
C-6 (explicit dylib resolution) — proven load-bearing, not theoretical: the worker binary run without DYLD_FALLBACK_LIBRARY_PATH aborts at dyld ('no LC_RPATH's found', exit 134) before any code runs; with it set to the executable directory it reaches the worker and exits 2 with its own message. Had the child been left to inherit it by luck, diarization would have failed on every run in a packaged build.
C-7 (threshold stays 0.9, build_config unchanged) — both byte-unchanged; existing assertions on Some(0.9) still pass. The reason is recorded as a short constraint plus an ADR-013 pointer rather than as narrative in the source.
